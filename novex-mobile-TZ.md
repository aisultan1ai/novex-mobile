# ТЗ: мобильное приложение Novex (`Novex-mobile`)

> Документ для исполнителя (разработчика, дизайнера или ИИ-агента). Его можно передать целиком:
> в нём есть всё, чтобы начать работу без доступа к коду бэкенда. Схемы запросов и ответов —
> в `openapi.json`, который выдаёт команда Novex (раздел 5.1).

---

## 1. Что делаем

**Novex** — агрегатор курьерских служб Казахстана. Клиент вводит маршрут и параметры посылки,
сравнивает цены и сроки нескольких перевозчиков (CSE, Exline, Azimuth и др.), оформляет и оплачивает
заказ, а потом отслеживает доставку. Заказ перевозчику передаёт Novex. Веб-версия уже работает.

**Задача:** клиентское мобильное приложение для iOS и Android. Оно работает с **тем же API**, что и
сайт; собственного бэкенда у приложения нет.

```
Сайт (Next.js)          ─┐
                         ├──►  API Novex  /api/v1  (FastAPI)  ──►  БД, бизнес-логика, перевозчики
Приложение (Novex-mobile)┘
```

**Пользователи приложения:**
- частное лицо — 1–2 посылки в месяц, всё с телефона;
- компания (юрлицо, ИП) — пакеты по 10–20 отправлений, адресная книга, оплата переводом или
  **по договору** (постоплата);
- получатель без аккаунта — открывает ссылку отслеживания.

Кабинеты перевозчика и администратора в приложение **не входят**: они остаются на сайте.

## 2. Репозиторий и окружение

- Отдельный git-репозиторий (на GitHub — `novex-mobile`). Локально папка **`Novex-mobile`** лежит рядом с основным проектом:
  ```
  PycharmProjects/
  ├── Novex/          ← бэкенд и сайт (не трогать)
  └── Novex-mobile/   ← этот проект
  ```
- Три окружения, адрес API берётся из конфигурации сборки, а не из кода:

  | Окружение | API | Назначение |
  |---|---|---|
  | `development` | `http://<локальный IP>:8000/api/v1` | разработка, локальный бэкенд |
  | `staging` | выдаёт команда Novex | тестирование, TestFlight / внутренний тест Google Play |
  | `production` | `https://<домен Novex>/api/v1` | сторы |

- В приложении **не должно быть секретов** (ключей перевозчиков, платёжных ключей, паролей).
  Всё секретное живёт на бэкенде.

## 4. Архитектура приложения

```
Novex-mobile/
├── app/                        # экраны (expo-router)
│   ├── (auth)/                 # вход, регистрация, восстановление пароля, подтверждение email
│   ├── (tabs)/                 # нижняя навигация
│   │   ├── index.tsx           # расчёт стоимости
│   │   ├── orders/             # заказы, деталь заказа, пакеты
│   │   ├── track.tsx           # отследить
│   │   ├── notifications.tsx
│   │   └── profile/            # профиль, адресная книга, договор, настройки
│   ├── quote/                  # результаты расчёта
│   ├── checkout/               # шаги оформления, оплата
│   ├── batches/                # «Несколько отправлений»
│   └── tracking/[number].tsx   # публичный трекинг (deep link)
├── src/
│   ├── api/
│   │   ├── schema.d.ts         # СГЕНЕРИРОВАНО из openapi.json, руками не править
│   │   ├── client.ts           # fetch-обёртка: базовый URL, токен, язык, обновление токена, ошибки
│   │   └── endpoints/          # функции по разделам: auth, shipping, orders, payments, batches…
│   ├── features/               # логика экранов: хуки react-query, формы, мапперы
│   ├── ui/                     # дизайн-система: tokens.ts, Button, Input, Card, StatusBadge…
│   ├── i18n/                   # ru.json, kk.json, настройка i18next
│   ├── store/                  # zustand: язык, тема, черновики
│   ├── lib/                    # форматирование денег, дат, телефонов, ИИН/БИН
│   └── config.ts               # адрес API и флаги окружения
├── assets/                     # шрифты, иконки, сплэш
├── app.config.ts, eas.json
└── .github/workflows/ci.yml    # lint + типы + тесты на каждый PR
```

**Правила:**
1. Экраны не ходят в `fetch` напрямую — только через `src/api` и хуки из `src/features`.
2. Тип каждого запроса и ответа берётся из `schema.d.ts`. Свои дубли типов API запрещены.
   Команда `npm run api:types` перегенерирует типы; CI падает, если они устарели.
3. Цвета, шрифты, отступы — только из `src/ui/tokens.ts`. Хекс-коды в экранах запрещены.
4. Все строки интерфейса — через `t('…')`, ни одной строки текстом в разметке.
5. Каждый экран обрабатывает 4 состояния: загрузка (скелетоны), пусто, ошибка (с «Повторить»), нет сети.

## 5. Контракт с бэкендом

### 5.1 Источник правды
- Команда Novex выдаёт `openapi.json` (артефакт сборки бэкенда или адрес staging). В проде
  документация API закрыта — это нормально.
- Базовый путь: `/api/v1`. Только HTTPS (кроме локальной разработки).

### 5.2 Авторизация
Авторизацию сайта не трогаем: у приложения свои эндпоинты входа (`/mobile/auth/*`, задача B1).
Аккаунты общие — тот же email и пароль, те же заказы. Cookie приложение не использует.

- `POST /mobile/auth/login` `{email, password, device_id}` →
  `{access_token, refresh_token, expires_in, profile}`.
- `POST /mobile/auth/refresh` `{refresh_token, device_id}` → новая пара
  `{access_token, refresh_token, expires_in}`. Старый refresh-токен сразу перестаёт работать —
  сохранять каждый раз новый.
- `POST /mobile/auth/logout` `{refresh_token, device_id}` — отзывает токен только этого устройства.
- `device_id` — случайный UUID, создаётся при первом запуске и хранится на устройстве.
- Access-токен живёт около 60 минут, refresh-токен — 30 дней; пока приложением пользуются, срок
  продлевается с каждым обновлением.
- Каждый запрос: заголовки `Authorization: Bearer <access_token>` и `X-Locale`.
- Клиент: при `401` — один раз вызвать `/mobile/auth/refresh` и повторить запрос; если не вышло — на
  экран входа. Параллельные запросы ждут одного общего обновления, а не обновляют каждый сам.
- Токены хранить только в `expo-secure-store`. При выходе — `/mobile/auth/logout` и очистка хранилища.
- Регистрация, восстановление пароля и подтверждение email — общие с сайтом (`/auth/*`, см. 5.6).
- Пока `/mobile/auth/*` нет в `openapi.json`, вход разрабатывается на моках по этой схеме.
- После первого входа — предложить вход по Face ID / отпечатку (локальная разблокировка
  сохранённого refresh-токена).

### 5.3 Язык
- Каждый запрос: заголовок `X-Locale: ru` или `X-Locale: kk`. Бэкенд по нему переводит тексты ошибок
  и уведомлений.
- Смена языка в приложении → `PATCH /auth/locale`, чтобы письма и push тоже приходили на этом языке.

### 5.4 Ошибки
- Формат: `{"detail": "текст"}` — текст уже на языке пользователя, его можно показывать как есть.
- `422` (ошибки полей): `{"detail": [{"loc": [...,"field"], "msg": "..."}]}` → показывать у
  конкретного поля формы.
- `429` — слишком много запросов: показать «Подождите минуту и повторите», не повторять автоматически.
- `5xx` / нет сети — экран ошибки с кнопкой «Повторить».

### 5.5 Ограничения частоты (действуют сейчас)
Расчёт стоимости — 30 в минуту, вход — 10 в минуту, **обновление токена — 20 в минуту**
(сейчас у `/auth/refresh`; лимит для `/mobile/auth/refresh` уточнит команда Novex), регистрация и восстановление пароля — 5 в минуту, поиск городов и ПВЗ CSE — 30 в минуту.
Лимиты считаются по IP. Не делать расчёт на каждое нажатие клавиши: только по кнопке «Рассчитать».
Обновление токена — одно на все параллельные запросы (иначе легко упереться в 20 в минуту).

### 5.6 Эндпоинты по экранам

| Экран / действие | Метод и путь |
|---|---|
| Вход, выход, обновление токена | `POST /mobile/auth/login`, `/mobile/auth/logout`, `/mobile/auth/refresh` (см. 5.2) |
| Регистрация | `POST /auth/register` (общая с сайтом) |
| Подтверждение email, повторное письмо | `POST /auth/verify-email`, `/auth/resend-verification` |
| Забыли пароль | `POST /auth/forgot-password`, `/auth/reset-password` |
| Профиль | `GET/PATCH /profile`, `POST /profile/change-password`, `PATCH /auth/locale` |
| Адресная книга | `GET/POST /profile/addresses`, `DELETE /profile/addresses/{id}` (редактирования нет — удалить и создать заново) |
| Расчёт | `POST /shipping/quote` → `GET /shipping/quote/{id}` |
| Выбор тарифа | `POST /shipping/quote/{id}/select` → `POST /orders/drafts/from-quote` |
| Города (откуда / куда) | **API нет** — статичный список 250 городов и районных центров Казахстана, как на сайте (`frontend/src/lib/cities.ts`: `KZ_CITIES` + казахские названия `KK_CITY_NAMES`; выдаёт команда Novex). В расчёт отправляется русское значение `value`, на экране — название на языке пользователя |
| Предпросмотр цены (CSE) | `POST /orders/drafts/{id}/cse-recalc` — «было → стало» на шаге деталей: при смене страхования, объявленной ценности, типа доставки, веса и габаритов. Запрос с задержкой 500 мс после последнего изменения, предыдущий отменять. Ответ `recalculated: false` или ошибка — показывать цену черновика. Для других перевозчиков не вызывать |
| Данные отправления | `PATCH /orders/drafts/{id}/shipment` — сохраняет данные; для CSE цена заказа фиксируется по этому пересчёту |
| Пункты выдачи CSE | `GET /carriers/cse/pvz?city=...` — список ПВЗ для доставки «до пункта» / «из пункта» (CSE). GUID выбранного пункта — в `sender_pvz_guid` / `recipient_pvz_guid` |
| К оплате | `POST /orders/drafts/{id}/checkout` |
| Оплата переводом | `POST /payments/orders/{id}/initiate-bank-transfer` → реквизиты и назначение платежа; `POST /payments/orders/{id}/upload-proof` (фото / PDF чека, multipart); `GET /payments/orders/{id}/payment-status` |
| Оплата по договору | `GET /contracts/me`; `POST /payments/orders/{id}/pay-by-contract` |
| Заказы | `GET /orders?page=&size=&statuses=`; `GET /orders/drafts/{id}`; `DELETE /orders/drafts/{id}` (черновик) |
| Отмена, перенос забора | `POST /orders/{id}/cancel`; `POST /orders/{id}/reschedule-pickup` (только CSE) |
| Трек заказа | `GET /orders/{id}/tracking` |
| Накладная PDF | `GET /orders/{id}/label` |
| Отзыв | `GET/POST /orders/{id}/review` |
| Публичный трекинг | `GET /tracking/{tracking_number}` (без входа) |
| Пакеты (компании) | `GET /batches/template.xlsx`, `POST /batches/parse-excel`, `POST /batches/quote`, `POST /batches`, `GET /batches`, `GET /batches/{id}`, `POST /batches/{id}/initiate-bank-transfer`, `/upload-proof`, `/pay-by-contract` |
| Уведомления | `GET /notifications`, `PATCH /notifications/{id}/read`, `POST /notifications/read-all` |

**Не использовать:** `POST /orders/drafts/{id}/pay/mock` (тестовая оплата, в проде выключена), все
`/admin/*`, `/carrier/*`, вебхуки.

### 5.7 Статусы заказа → что показывать

| Группа в приложении | Цвет | Статусы API |
|---|---|---|
| Оформляется | серый `#8FA3B2` | `draft`, `shipment_details_completed`, `ready_for_checkout` |
| Ждёт оплаты | серый | `awaiting_payment`, `payment_rejected` (с причиной и «загрузить чек заново») |
| Оплата проверяется | серый | `payment_under_review` |
| Передаётся перевозчику | серый | `paid`, `dispatch_queued`, `dispatch_failed`, `pending_manual`, `pending_manual_dispatch` |
| В пути | оранжевый `#F5A623` | `sent_to_carrier`, `picked_up`, `in_transit`, `arrived`, `out_for_delivery`, `customs_hold` |
| Проблема | красный `#E24B4A` | `delivery_failed` |
| Доставлен | зелёный `#12B886` | `delivered` |
| Возврат | серый | `return_requested`, `return_in_progress`, `returned` |
| Отменён | серый | `cancelled` |

Название статуса всегда текстом и иконкой, не только цветом. Неизвестный статус → «Обрабатывается».

## 6. Дизайн

### 6.1 Бренд (только эти цвета)
| Токен | HEX | Где |
|---|---|---|
| navy | `#0B2545` | главные кнопки (белый текст), заголовки; нажатие `#0E2E5C` |
| cyan | `#22C9E0` | точечный акцент: выбранная карточка тарифа (рамка + свечение `rgba(34,201,224,0.18)`), активная вкладка, прогресс. Большие площади не заливать |
| steel | `#3E6E8A` | второстепенные иконки |
| cloud | `#F1F5F9` | подложки, светлые бейджи |
| ink / muted / line | `#0E1826` / `#5F6E7E` / `#E2E8EE` | текст / вторичный текст / границы |
| фон | `#FAFAFA`, карточки белые | |

- **Шрифты:** Space Grotesk 500/700 — заголовки и цены, **от 24 pt**; Inter 400/500/600 — весь интерфейс, до 20 pt.
- **Логотип:** знак-«узел» (голубой центральный кружок, три линии к точкам) + «novex» строчными, Space Grotesk 700. Файлы выдаёт команда Novex.
- **Стиль:** спокойный, надёжный; много воздуха; скругления 12–16 (карточки) и 10–12 (кнопки); мягкие тени; линейные иконки (Lucide); без градиентов и стоковых иллюстраций.
- **Тёмная тема:** фон `#0E1826`, карточки чуть светлее, cyan — акцент, контраст не ниже AA.

### 6.2 Язык и форматы
- Русский и казахский; выбор при первом запуске и в профиле. Казахские строки на 15–25% длиннее — вёрстка не должна обрезать текст.
- Деньги `15 000 ₸`, даты `29 октября`, время 24 ч, телефон `+7 701 000 00 00`, ИИН/БИН 12 цифр.
- Переводы взять из сайта (`frontend/messages/ru.json`, `kk.json` — выдаёт команда Novex) и дополнить мобильными строками.

### 6.3 Навигация
Нижняя панель: **Расчёт**, **Заказы**, **Отследить**, **Уведомления**, **Профиль**. У компаний в «Заказах» — переключатель «Заказы / Несколько отправлений».

### 6.4 Экраны (MVP)
1. **Первый запуск:** сплэш, выбор языка, 2–3 слайда онбординга (пропускаемые).
2. **Вход / регистрация:** email + пароль; тип клиента (частное лицо / компания), ИИН или БИН, обязательное согласие на обработку персональных данных; подтверждение email; восстановление пароля; биометрия.
3. **Расчёт:** откуда / куда (поиск по встроенному списку городов Казахстана, см. 5.6; недавние сверху), тип (документы / посылка / груз), вес, габариты, количество мест, быстрые размеры S/M/L. Кнопка «Рассчитать» закреплена внизу.
4. **Тарифы:** карточки перевозчиков — логотип, тариф, цена крупно, срок; бейджи «Дешевле всех» (рамка navy) и «Быстрее всех»; выбранная — рамка cyan; сортировка по цене / сроку; пустое состояние «На этот маршрут перевозчиков нет».
5. **Оформление (4 шага с прогрессом):** отправитель → получатель (адресная книга / новый) → детали (дата и окно забора, вложение, объявленная ценность, доп. услуги, тип доставки; цена пересчитывается с анимацией) → проверка. Черновик сохраняется.
6. **Оплата:** перевод — реквизиты с кнопками «Скопировать», назначение платежа, загрузка чека (камера / галерея / файл); по договору — для компаний с активным договором. Состояния: ждём оплату, чек на проверке, оплачено, чек отклонён (причина + загрузить заново).
7. **Заказы:** список с фильтрами (активные / доставлены / отменены) и поиском; деталь — таймлайн статусов, трек-номер с копированием, плановая дата, накладная PDF (открыть / поделиться), «Перенести забор» (CSE), «Отменить», «Повторить заказ», отзыв после доставки.
8. **Отмена:** лист с причиной. До оплаты — сразу; после оплаты — «возврат оформит администратор, обычно 3–5 рабочих дней»; блок «Заявка на рассмотрении» с ответом. Если заказ входит в пакет с общим забором (`group_pickup_order_ids` не пуст) — предупредить, что отменятся и эти заказы.
9. **Несколько отправлений (компании):** общий отправитель, режим «разные адреса / один адрес», получатели карточками (не таблицей), добавление из адресной книги, импорт Excel с ошибками по строкам, расчёт пакета («самый дешёвый в каждой строке» / «один перевозчик»), один платёж на пакет, страница пакета со статусами.
10. **Отследить:** ввод номера или скан штрихкода; публичный экран трекинга для ссылок (без входа): текущий статус крупно, плановая дата, таймлайн, поддержка.
11. **Уведомления:** лента, «прочитано», переход к заказу; push (после задачи B2).
12. **Профиль:** данные, ИИН/БИН, компания, договор (номер, статус, долг), адресная книга, язык, тема, уведомления, поддержка, смена пароля, выход, удаление аккаунта (обязательно для App Store).

### 6.5 Принципы UX
- Цена и срок видны до оплаты; изменение цены — явно «было → стало».
- Минимум ввода: автодополнение, адресная книга, повтор заказа, правильные клавиатуры, камера.
- Одна главная кнопка на экран, закреплена внизу, высота от 48 pt.
- Ошибки — у поля и понятным языком.
- Необратимые действия (отмена, удаление) — с подтверждением и объяснением последствий.
- Доступность: контраст AA, области нажатия от 44×44 pt, крупный системный шрифт без поломки вёрстки, подписи для экранного диктора.
- Анимации 150–250 мс, уважать «уменьшить движение».

## 7. Нефункциональные требования

- **Безопасность:** токены только в secure store; не логировать токены, пароли, ИИН, телефоны (в том числе в Sentry); только HTTPS; блокировка скриншотов не нужна.
- **Офлайн:** последние заказы и статусы доступны без сети с пометкой «обновлено N минут назад»; действия, требующие сети, — с понятным сообщением.
- **Производительность:** холодный старт до 2 с на среднем Android; списки виртуализированы (`FlashList`); изображения сжимаются перед загрузкой (чек — до ~2 МБ).
- **Обновления:** при старте проверять минимальную версию (задача B4) — если устарела, экран «Обновите приложение».
- **Deep links:** `https://<домен>/tracking/{номер}` открывает экран трекинга в приложении (Universal Links / App Links), если приложение установлено.
- **Качество:** unit-тесты на клиент API (обновление токена, ошибки), форматтеры и маппинг статусов; тесты ключевых экранов; CI на каждый PR.

## 10. Что сдать

1. Репозиторий `Novex-mobile` с кодом, README (запуск, окружения, генерация типов, сборка) и CI.
2. Макеты (Figma или аналог): все экраны MVP в светлой теме, ключевые — в тёмной и на казахском, размеры iPhone 393×852 и Android 360×800, состояния загрузки / пусто / ошибка / офлайн.
3. Дизайн-система в коде (`src/ui`) и в макетах: цвета, типографика, отступы (сетка 4/8), кнопки, поля, карточка тарифа, бейдж статуса, таймлайн, bottom sheet, таб-бар, тосты, скелетоны.
4. Сборки для внутреннего тестирования на каждом этапе; в конце — публикация в сторах.

## 11. Критерии приёмки MVP

- Частное лицо с нуля за ≤ 3 минуты: регистрация → расчёт → оформление → оплата переводом с загрузкой чека.
- Компания оформляет пакет из 10 отправлений и оплачивает по договору.
- Получатель открывает ссылку трекинга и видит статус без входа.
- Все экраны работают на русском и казахском без обрезанного текста; светлая и тёмная тема.
- После истечения access-токена пользователь не вылетает на экран входа (обновление работает).
- Нет падений в Sentry на сценариях выше; CI зелёный.

## 12. Не входит

Кабинеты перевозчика и администратора, планшетная вёрстка, веб-версия приложения, онлайн-оплата
картой (будет, когда появится на бэкенде), собственный бэкенд приложения.

**Про Kaspi.** На бэкенде есть заготовка: провайдер Kaspi и приём уведомлений об оплате
(`/payments/kaspi/webhook`, в проде выключен, пока не настроен договор с Kaspi). Эндпоинта, через
который клиент начинает оплату Kaspi, пока нет. Экран оплаты проектировать так, чтобы способ «Kaspi»
добавлялся одной строкой списка способов; сроки подключения согласовать с командой Novex.
